Branch: `feature/experience-graph`.
Nothing in these bundles is pushed to GitHub / GitCode from the authoring
side. Apply the zips locally, run the commands below, then commit yourself.

## 1. What is in scope / out of scope

Already covered by unit tests (`tests/ut/exgraph/`,
`tests/ut/skill_evolver/test_exgraph_context.py`):

- ingest of recorder JSONL into cases / steps;
- SkillDoc scan of `skills/.proposals` vs accepted `skills/`;
- `extract_episodes` reuse (no fork of detectors);
- `FIXED_BY` edges for `user_correction` and `error_recovery`;
- overlay recipes via `mine_cross_session`;
- fail-open + `MSAGENT_EXGRAPH_DISABLED` on the evolver hook;
- `CROSS_SESSION_LIMIT = 20` and `select_trajectories` left untouched.

That is not enough to claim **value for Skill Evolver**. Unit tests prove
the graph writes nodes. They do not prove the classify prompt is richer
than episode bullets, and they do not show the graph growing.

Intensive tests therefore do four extra things:

1. Feed **multi-thread, recorder-shaped trajectories** (not one-event
   stubs): a failing Profiler session, a successful reuse session, and
   an Accuracy control session that must not own Profiler recipes.
2. Run an **A/B** of the exact object Evolver classifies —
   `build_evidence_bundle` — with the graph appendix off vs on.
3. Assert the appendix adds **relations** (`FIXED_BY`, per-case outcome,
   tool path, cross-session recipes, SkillDoc pointer) and does **not**
   invent new `Evidence:` seqs or grow the last-N pool.
4. Snapshot the union graph after each trajectory and write a
   **self-contained HTML picture** that highlights what is new.

Still not done (on purpose):

- call the classify / generate LLM;
- write a `SKILL.md` and score it with a human rubric;
- crawl a customer project’s private `trajectories/*.jsonl` (live
  procedure in §8, run on your machine).

---

## 2. What “value” means here

Skill Evolver already emits independent episode bullets
(`error_recovery`, `user_correction`, `approval_denied`, …).
Duplicating those bullets in the graph would be noise.

The graph is valuable only when it adds structure the detectors do not
emit:

| Signal | Evolver-only bundle | Bundle + stored graph |
| --- | --- | --- |
| Episode kinds + evidence seqs | yes | same set (must not grow) |
| Which *case* was fixed by which later case | no | `FIXED_BY` |
| Per-turn outcome (`golden` / `warning` / `unknown`) | no | `outcome=` on each case |
| Tool path of the turn (recipe grain) | no | `tools=bash → read_file` |
| Recipe that exists only when two threads share an n-gram | no | `Recipes instantiated` |
| Skill proposal that cites this thread | no | SkillDoc line when planted |
| `CROSS_SESSION_LIMIT` | 20 | 20 (unchanged) |

Observed on the fixture corpus (`exgraph_evolver_value_report.md`,
regenerated by `test_write_value_report`):

- evolver-only bundle: 5 episodes, evidence_score 3.80, 3502 chars;
- after `attach_stored_graph`: 4048 chars (**+546**), 2 `FIXED_BY`
  edges, 2 cross-session recipes, appendix contains
  `Experience graph` / `fixed_by` / `outcome=` / `Recipes instantiated`;
- appendix text contains **no** `Evidence:` lines, so classify
  `valid_seq` stays the evolver set.

## 5. Apply order

On `feature/experience-graph`, from the msAgent repository root:

```
# 1. product
unzip -o /path/to/exgraph-p1.zip
# follow that zip's APPLY / copy src/msagent/exgraph and hook files

# 2. intensive fixtures + A/B tests
unzip -o /path/to/exgraph-intensive-tests.zip
cp -a exgraph-intensive-tests/tests/it/exgraph/. tests/it/exgraph/
cp -a exgraph-intensive-tests/tests/fixtures/trajectories/. tests/fixtures/trajectories/

# 3. growth visualizer + 8th test + export viz command
unzip -o /path/to/exgraph-growth-viz.zip
cp -a exgraph-growth-viz/src/msagent/exgraph/visualize.py src/msagent/exgraph/visualize.py
cp -a exgraph-growth-viz/src/msagent/exgraph/export.py src/msagent/exgraph/export.py
cp -a exgraph-growth-viz/tests/it/exgraph/test_evolver_value.py tests/it/exgraph/test_evolver_value.py
```

Step 3 overwrites the intensive test file with the 8-test version.
`export.py` only adds the `viz` command; `build` / `show` / `export`
stay the same.

Dependencies already in the project: pytest, trajectory recorder reader,
Skill Evolver `features` / `bundle`, ExGraph P1. No new third-party
packages. The HTML file has no CDN.

## 6. How to run

Always isolate from `tests/conftest.py` plugins the clone may not need:

```
# intensive suite (8 tests, including growth HTML)
python -m pytest tests/it/exgraph/test_evolver_value.py -q --noconftest

# P1 unit + intensive
python -m pytest tests/ut/exgraph \
  tests/ut/skill_evolver/test_exgraph_context.py \
  tests/it/exgraph -q --noconftest

# regenerate the A/B markdown report
EXGRAPH_VALUE_REPORT=$PWD/artifacts/exgraph_evolver_value_report.md \
  python -m pytest tests/it/exgraph/test_evolver_value.py::test_write_value_report \
  -q --noconftest

# regenerate only the growth picture
EXGRAPH_GROWTH_HTML=$PWD/artifacts/exgraph_growth_demo.html \
  python -m pytest tests/it/exgraph/test_evolver_value.py::test_growth_html_highlights_new_over_trajectories \
  -q --noconftest

# same picture without pytest (needs visualize.py on PYTHONPATH)
python -m msagent.exgraph.visualize \
  --fixtures tests/fixtures/trajectories \
  -o artifacts/exgraph_growth_demo.html

python -m msagent.exgraph.export viz -o artifacts/exgraph_growth_demo.html
```

### Environment variables

| Variable | Effect |
| --- | --- |
| `MSAGENT_EXGRAPH_DISABLED=1` | Kill switch. No shard / overlay writes. Evolver bundle unchanged. Also accepts `true` / `yes` / `on`. YAML `exgraph.enabled: false` is equivalent. |
| `EXGRAPH_VALUE_REPORT` | Path written by `test_write_value_report`. Default: `artifacts/exgraph_evolver_value_report.md` if that folder exists, else next to the test file. |
| `EXGRAPH_GROWTH_HTML` | Path written by `test_growth_html_highlights_new_over_trajectories`. Default: `artifacts/exgraph_growth_demo.html` if that folder exists, else next to the test file. |

`show` / `export` of an already-written shard still work when the kill
switch is on. `build`, `remember_thread`, the evolver hook, and `viz`
must not write.

## 7. Growth picture (boss demo)

Open `exgraph_growth_demo.html` in a browser. No server. Press **Play**.

Gold ring + `NEW ·` label = node or edge that appeared on the current
trajectory. “Hide LLM steps” is on by default.

| Step | Trajectory | What lights up as new | Pass condition |
| --- | --- | --- | --- |
| 1 | Profiler `thread-signals` | Thread, task, cases, tool steps, episodes, `FIXED_BY`, SkillDoc | At least one `FIXED_BY` |
| 2 | Profiler `thread-reuse` | Second thread + Recipe `bash>read_file` + `INSTANTIATES` | Recipe exists; both Profiler cases may instantiate it |
| 3 | Accuracy `thread-accuracy` | Isolated Accuracy cluster | `case:run-a1` is **not** an `INSTANTIATES` source |

If step 2 has no Recipe, the two Profiler fixtures no longer share a
tool n-gram — fail the intensive suite, do not present the picture.

## 8. Live-data procedure (real project trajectories)

Fixtures prove the contract. To show the same value on a real working
directory:

1. Confirm recorder JSONL exist:

   ```
   ls <project>/.msagent/trajectories/   # or the project-state path you use
   ```

2. Build shards (P1 CLI). This does not call the LLM:

   ```
   python -m msagent.exgraph.export build --all --working-dir /path/to/project
   python -m msagent.exgraph.export show --thread <thread_id>
   ```

3. Control arm — Evolver must behave as before:

   ```
   MSAGENT_EXGRAPH_DISABLED=1
   # then /skill-mine or the evolver CLI you already use
   ```

   Classify prompt / proposal under `skills/.proposals/<thread>/`
   must match pre-P1 shape (no `## Experience graph (stored)` section).

4. Treatment arm — unset the kill switch, mine the same thread again.
   Diff the classify bundle or the proposal draft. Value is present if
   and only if:

   - a `## Experience graph (stored)` section appears;
   - it lists this thread’s cases with `outcome=` and tool paths;
   - `FIXED_BY` appears when the session actually contains a correction
     or recovery;
   - `Recipes instantiated` appears only when another recent thread
     shares a tool n-gram;
   - no new `Evidence: seq=…` lines were added;
   - the last-N pool is still 20 (`CROSS_SESSION_LIMIT`).

5. Optional picture from that project’s fixtures / JSONL:

   ```
   python -m msagent.exgraph.visualize \
     --fixtures <project>/.msagent/trajectories \
     -o artifacts/exgraph_growth_demo.html
   ```

6. Record the A/B diff (char count, facts present, recipe count) in the
   same layout as `exgraph_evolver_value_report.md`. Do not commit
   customer JSONL.

## 9. Pass / fail criteria

Ship-ready for this slice when:

- `pytest tests/it/exgraph/test_evolver_value.py --noconftest` is
  **8 green** on a tree that already has P1 + `visualize.py`;
- the generated report shows a positive char delta and at least one
  `FIXED_BY` on the signals thread;
- `exgraph_growth_demo.html` opens, Play walks three steps, step 2
  shows a Recipe, step 3 does not attach that Recipe to Accuracy;
- `MSAGENT_EXGRAPH_DISABLED=1` makes intensive + unit hook tests pass
  with zero shard writes;
- `grep -n CROSS_SESSION_LIMIT src/msagent/skill_evolver/` is still 20.

Fail / do not claim value when:

- the appendix only repeats episode names already in the bundle;
- `valid_seq` grows;
- recipes leak the Accuracy control thread into a Profiler skill;
- ingest or the hook raises into `/skill-mine` (must fail-open);
- the HTML is a static dump with no per-step `new_node_ids`.

Without `visualize.py` on `PYTHONPATH`, test 8 uses `demo_snapshots()`
and can still go green. For a boss demo, run it on a tree that has P1
so the picture is built from live `remember_thread`.
