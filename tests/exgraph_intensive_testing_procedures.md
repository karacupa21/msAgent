# ExGraph intensive tests — procedures and value proof

Status: intensive A/B suite exists and was run against recorder-shaped
fixtures on a Krusty clone with the P1 overlay (7 passed).
Branch: `feature/experience-graph`.
This bundle contains **tests + fixtures + this document only**. Product
source stays in `exgraph-p1.zip`.

## 1. Answer: is it time for intensive tests?

Yes — for the layer that is already implemented. Not yet for a live LLM
gold-set of finished `SKILL.md` files.

What is already covered by unit tests (`tests/ut/exgraph/`,
`tests/ut/skill_evolver/test_exgraph_context.py`):

- ingest of recorder JSONL into cases / steps;
- SkillDoc scan of `skills/.proposals` vs accepted `skills/`;
- `extract_episodes` reuse (no fork of detectors);
- `FIXED_BY` edges for `user_correction` and `error_recovery`;
- overlay recipes via `mine_cross_session`;
- fail-open + `MSAGENT_EXGRAPH_DISABLED` on the evolver hook;
- `CROSS_SESSION_LIMIT = 20` and `select_trajectories` left untouched.

That is not enough to claim **value for Skill Evolver**. Unit tests prove
the graph writes nodes. They do not prove that the classify prompt is
richer in a way the evolver cannot already see from episode bullets.

Intensive tests therefore do three extra things:

1. Feed **multi-thread, recorder-shaped trajectories** (not one-event
   stubs): a failing Profiler session, a successful reuse session, and
   an Accuracy control session that must not own Profiler recipes.
2. Run an **A/B** of the exact object Evolver classifies —
   `build_evidence_bundle` — with the graph appendix off vs on.
3. Assert the appendix adds **relations** (`FIXED_BY`, per-case outcome,
   tool path, cross-session recipes, SkillDoc pointer) and does **not**
   invent new `Evidence:` seqs or grow the last-N pool.

What intensive tests still do **not** do (on purpose):

- call the classify / generate LLM;
- write a `SKILL.md` and score it with a human rubric;
- crawl a customer project’s private `trajectories/*.jsonl` (that is
  the live procedure in §7, run on your machine).

Those two steps need a real project and a reviewer’s eye. The suite
gives you the protocol and the control (`MSAGENT_EXGRAPH_DISABLED=1`).

## 2. What “value” means here

Skill Evolver already emits independent episode bullets
(`error_recovery`, `user_correction`, `approval_denied`, …).
Duplicating those bullets in the graph would be noise.

The graph is valuable only when it adds structure the detectors do not
emit:

| Signal | Evolver-only bundle | Bundle + stored graph |
| --- | --- | --- |
| Episode kinds + evidence seqs | yes | same set (must not grow) |
| Which *case* was fixed by which later case | no | `FIXED_BY` |
| Per-turn outcome (`golden` / `warning` / `unknown`) | no | `outcome=` on each case |
| Tool path of the turn (recipe grain) | no | `tools=bash → read_file` |
| Recipe that exists only when two threads share an n-gram | no | `Recipes instantiated` |
| Skill proposal that cites this thread | no | SkillDoc line when planted |
| `CROSS_SESSION_LIMIT` | 20 | 20 (unchanged) |

Observed on the fixture corpus (see
`exgraph_evolver_value_report.md`, regenerated by
`test_write_value_report`):

- evolver-only bundle: 5 episodes, evidence_score 3.80, 3502 chars;
- after `attach_stored_graph`: 4048 chars (**+546**), 2 `FIXED_BY`
  edges, 2 cross-session recipes, appendix contains
  `Experience graph` / `fixed_by` / `outcome=` / `Recipes instantiated`;
- appendix text contains **no** `Evidence:` lines, so classify
  `valid_seq` stays the evolver set.

That is the demonstration requested: ExGraph improves the *context*
Evolver classifies from, without replacing Evolver or widening its
trajectory pool.

## 5. How to apply this bundle

From the msAgent repo root, on `feature/experience-graph`, after P1
source is already in the tree:

```
unzip -o /path/to/exgraph-intensive-tests.zip
# files land under tests/… and this folder’s markdown at repo root
# if the zip root is exgraph-intensive-tests/, copy:
cp -a exgraph-intensive-tests/tests/. tests/
```

See `APPLY.md` in the zip root.

Dependencies already in the project: pytest, the trajectory recorder
reader, Skill Evolver `features` / `bundle`, ExGraph P1
(`remember_thread`, `rebuild_overlay`, `attach_stored_graph`).
No new third-party packages.

## 6. How to run

Always isolate from `tests/conftest.py` plugins that the Krusty clone
does not need:

```
# intensive suite only
python -m pytest tests/it/exgraph/test_evolver_value.py -q --noconftest

# P1 unit + intensive
python -m pytest tests/ut/exgraph tests/ut/skill_evolver/test_exgraph_context.py tests/it/exgraph -q --noconftest

# write the human report next to the test or under artifacts/
EXGRAPH_VALUE_REPORT=$PWD/artifacts/exgraph_evolver_value_report.md \
  python -m pytest tests/it/exgraph/test_evolver_value.py::test_write_value_report -q --noconftest
```

Expected: **7 passed** on the intensive file.

`test_write_value_report` writes
`artifacts/exgraph_evolver_value_report.md` when that directory exists,
otherwise `tests/it/exgraph/exgraph_evolver_value_report.md`. Override
with `EXGRAPH_VALUE_REPORT`.

## 7. Live-data procedure (real project trajectories)

Fixtures prove the contract. To show the same value on a real msAgent
working directory:

1. Confirm recorder JSONL exist:

   ```
   ls <project>/.msagent/trajectories/   # or the project-state path you use
   ```

2. Build shards (P1 CLI). This does not call the LLM:

   ```
   python -m msagent.exgraph.export build --all --working-dir /path/to/project
   python -m msagent.exgraph.export show --thread <thread_id>
   ```

3. Control arm — Evolver must behave as before:

   ```
   MSAGENT_EXGRAPH_DISABLED=1
   # then /skill-mine or the evolver CLI you already use
   ```

   Classify prompt / proposal under `skills/.proposals/<thread>/`
   must match pre-P1 shape (no `## Experience graph (stored)` section).

4. Treatment arm — unset the kill switch, mine the same thread again.
   Diff the classify bundle or the proposal draft. Value is present if
   and only if:

   - a `## Experience graph (stored)` section appears;
   - it lists this thread’s cases with `outcome=` and tool paths;
   - `FIXED_BY` appears when the session actually contains a correction
     or recovery;
   - `Recipes instantiated` appears only when another recent thread
     shares a tool n-gram;
   - no new `Evidence: seq=…` lines were added;
   - the last-N pool is still 20 (`CROSS_SESSION_LIMIT`).

5. Record the diff (char count, facts present, recipe count) in the
   same layout as `exgraph_evolver_value_report.md`. Do not commit
   customer JSONL.

Kill switch and YAML `exgraph.enabled: false` are equivalent. Inspection
`show` / `export` of an already-written shard still works when disabled.

## 8. Pass / fail criteria

Ship-ready for this slice when:

- `pytest tests/it/exgraph/test_evolver_value.py --noconftest` is 7 green
  on a tree that already has P1;
- the generated report shows a positive char delta and at least one
  `FIXED_BY` on the signals thread;
- `MSAGENT_EXGRAPH_DISABLED=1` makes intensive + unit hook tests pass
  with zero shard writes;
- `grep -n CROSS_SESSION_LIMIT src/msagent/skill_evolver/` is still 20.

Fail / do not claim value when:

- the appendix only repeats episode names already in the bundle;
- `valid_seq` grows;
- recipes leak the Accuracy control thread into a Profiler skill;
- ingest or the hook raises into `/skill-mine` (must fail-open).
